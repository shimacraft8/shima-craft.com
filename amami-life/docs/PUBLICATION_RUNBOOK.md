最新の初版スコープ・登録・署名・更新手順は [STORE_RELEASE.md](STORE_RELEASE.md)。Apple/Google未登録、GitHub本人不一致を継続確認済みです。

この文書は公開を実行する許可ではありません。現状はローカル開発版で、審査提出できる完成状態には達していません。

## 1. 所有者と承認を先に確定

GitHub APIで確認したログインは `camiordersystem-maker`、既存サイトremoteの所有者は `shimacraft8`。不一致が未解消のためpush・公開操作は行いません。既存SHIMA CRAFTサイトへこのプロジェクトを上書きしません。

公開主体が個人/組織のどちらか、専用の新規アプリrepoの所有者、GitHub/Cloudflare/Expo/Apple/Googleの各アカウントを人が確認します。ログイン変更・権限追加・remote設定・外部リソース作成は勝手に実行しません。既存サイト本番とローカルチェックアウトの一致も未確認です。

## 2. ローカルの公開候補を検証

```bash
npm ci
npm run build
npm run typecheck
npm run lint
npm test
npm run inspect:jma
```

公開依存の監査を再実行し、現在残る29件の警告について修正版・到達可能性・対応方針を記録します。`npm audit fix --force` でExpoを無検証に大きく変更しません。原資料・旧サイトを変更せず、新プロジェクト内で修正します。

ホーム気温は公式アメダスへ置換済み。観測品質・時刻・鮮度を維持し、デザイン比較用デモを本番に含めません。現行警報を扱う場合は初期状態の確立と取消/解除・欠落検出の受入条件を満たします。[次の優先順位](NEXT_ROADMAP.md)、[実機確認](DEVICE_QA.md)のP0を完了し、差分のUIレビューを受けます。

## 3. バックエンドを承認後に準備

専用HTTPS API、ソース別キャッシュ/流量制限、永続イベント履歴、再取得、停止検知、アラート、ログ保存期間を準備します。Nodeのloopbackサーバーをそのままインターネットへ公開しません。天気JSONは非バージョン化の公開Web用提供で、SLAや正式API契約を確認済みとはしません。

Cloudflare Worker/D1等のアカウント、リソース名、費用上限、ドメイン、CORS許可元、障害時の対応者を確認してから作成・デプロイします。API鍵・通知鍵・秘密設定をアプリや `EXPO_PUBLIC_*` に埋め込みません。実機クライアントの公開API許可元は、承認後に明示的に追加します。

## 4. ストア・テスト配布を承認後に準備

App ID/package名、表示名、アイコン、スプラッシュ、プライバシー/サポート/訂正窓口URL、利用規約、出典、取得データの申告、権限説明、ストア説明文・スクリーンショットを確定します。独自の昼夜アイコン/起動画面はローカル作成済み。OS上の実機確認と最終掲載素材は未完です。

Apple/Googleの登録名義と表示される個人/組織名を確認します。Googleの新規個人アカウントでは公開前のテスト要件があるため、条件と対象者を事前に確認します。費用/要件は変更され得るので直前に [公開ゲート](RELEASE_GATES.md) の公式リンクで再確認します。

EASプロジェクト作成、クラウドビルド、署名鍵、TestFlight/Playテストの登録・アップロードは外部操作です。具体的な配布先と内容の確認後に実行します。現状の `expo export` はJS/Hermes/Web出力で、署名済みipa/apk/aabの作成や配布ではありません。

## 5. 一般公開の最終確認

実機のP0、依存監査、データ条件、運用窓口、名義、費用、デモ除去、誤警報/取り逃しの試験記録を揃えます。ストア提出・公開、GitHub push、バックエンドの本番デプロイはそれぞれ対象と変更内容を提示し、明示的な承認を受けてから実行します。

公開後はソース停止/鮮度/スキーマ変更、公式リンク、翌年の潮汐、事業者の取り下げ、クラッシュを継続監視する担当と周期を決めます。アプリ内に現在状態が不明なときの公式導線を残します。
