# テスト計画とDefinition of Done（Codexの完了条件）

## 情報の正しさ

- [ ] 日付境界：23:59/00:00 JST、端末の海外タイムゾーン、閏日を検証。
- [ ] 日の出/入り：名瀬・笠利・古仁屋の地点差、方位角の北=0°/東=90°を国立天文台等で検算。
- [ ] 潮汐：基準局IDの確認、別地点に名瀬の値を流用しない。潮位表示cm・満干の複数件・欠損・翌日またぎ。
- [ ] 空港：便の運航日・空港名・情報発表元、便の遅延/欠航は元発表で確認できること。契約無しなら公式ページを開くのみ。
- [ ] フェリー：通常/条件付き/欠航/寄港地変更、上り下り便・日付・会社を混同しない。
- [ ] バス：改正前の時刻表を現在時刻表として使用しない。
- [ ] 事業者電話帳：電話番号の格式、発信が正しいか、更新日、地域、掲載取り下げ対応。

## 防災（最優先）

- [ ] 地震履歴とEEWを別データ型で表示。震度未判定の「---」を「震度0」としない。
- [ ] 津波発表/解除/訂正をテスト。地震履歴の「最近津波記事なし」から現在無警報と推測しない。
- [ ] 発達する熱帯低気圧→台風→温帯低気圧への変化を同一系統のイベントとして扱う。台風でなくなった後の大雨・高波を無視しない。
- [ ] 旧Workerの「過去72h関連発表」を「活動中0件」と誤表示しない。
- [ ] 配信停止、XML変更、JSON不正、遅延、部分失敗、過去キャッシュ、時計のズレを注入。
- [ ] 全ての警報系に出典/発表・取得時刻/鮮度/公式リンク。「不明」時のUIを強制テスト。
- [ ] 通知の重複/取消/訂正/誤対象地域/未許可/消音/バックグラウンド/端末再起動などを検証。秒単位保証を謳わない。

## UI・UX・デザイン

- [ ] 375/390/430px相当とiPad表示、safe areas、システムジェスチャ/Android戻る。
- [ ] タップ44pt以上、重要ボタンの文言、VoiceOver/TalkBack、Dynamic Type 200%、色覚多様性。
- [ ] 全5タブに読み込み中/データ無し/通信失敗/期限切れ/オフラインの状態。
- [ ] 監修済みのデザインルールを「見た目」だけでなく全コンポーネントで適用。重要情報は色単体に頼らない。
- [ ] 初回導線：位置権限拒否でも手動エリア選択、アカウント作成不要で今日/移動/防災を閲覧。
- [ ] UI Pocketの分析と新デザインを並べてレビュー。ただし模倣しない。

## 開発/運用

- [ ] TypeScript strict、Lint、ユニット/統合/スモークテスト成功。実行したコマンド/結果を記録。
- [ ] iOS/Android端末またはエミュレータで起動確認。環境上無理なら**未実施と明記**。
- [ ] 一覧APIのキャッシュと最大リクエスト制限、失敗の監視、出典リンクの生存確認。
- [ ] `.env*` とキー・認証情報の公開無し、GitHub/Cloudflareの対象アカウント確認。
- [ ] プライバシーポリシー、データ訂正窓口、利用条件、ストアアセット、クラッシュ監視計画。
- [ ] レビュー済みのデータ利用条件が無いソースの取得は**公式リンクで代替**。
- [ ] GitHub push / deploy / AppStoreやGooglePlay提出はユーザーの明示許可後のみ。

## 報告フォーマット

1. UI比較資料（2〜3案、選定理由、スクショ）
2. 機能一覧：implemented / partial / external-link / blocked / future
3. データソース：verified / permission-pending / not-verified、具体的な出典
4. 変更ファイル・主要アーキテクチャ
5. 実行したテストと結果・残課題（スクショ付き）
6. 次の承認が必要な項目、公開までの見積もりとコスト（根拠記載）
