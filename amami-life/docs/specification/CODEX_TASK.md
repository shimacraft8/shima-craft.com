# Codexへの実装依頼 — AMAMI LIFE 0→1構築

あなたはSHIMA CRAFTのiPhone/Android向け「AMAMI LIFE」のリードエンジニア兼UI/UXデザイン実装担当です。目的は奄美大島の旅行・暮らしに必要な情報を、美しく、正確に、信頼できるアプリにまとめ、後日App Store・Google Playに公開できる水準へ育てることです。

## 最初に必ずやること

1. `START_HERE.md` および `docs/` の全ファイル、`visual-prototype/index.html` を確認してください。`reference/legacy-v0.3/` は**参考コード**として監査し、新UIを無条件に上書きしない。
2. `pwd`, `git status --short`, `git remote -v`, `gh auth status`, `gh api user --jq '{login,email}'` などで作業環境とログイン中の**GitHubアカウント**を確認。顧客/本業のリポジトリへ誤pushしない。シークレットを表示しない。
3. もしフォルダ内がGit未初期化なら、既存リモートを勝手に設定しない。新しいローカルrepoにする場合も当該作業フォルダ配下で安全に。
4. SHIMA CRAFTの既存 `https://shima-craft.com/amami-tide` のソースは、ユーザーがアクセス権を持つリポジトリ内で**読み取りだけ**で調査。所定の場所が見つからない場合は、見つかったふりをせずパスを確認する。外部サイトのHTMLだけではバックエンドの取得方式は証明できない。

## Design First（このフェーズを省略しない）

- UI Pocket https://www.ui-pocket.com/mobile のようなUIギャラリー、およびApple HIG/Material 3/日本語UI Kitを分析する。**本当に閲覧できた例だけ**列挙する。
- 現在のv0.3の『AIがそれっぽく作った画面』を踏襲せず、`docs/DESIGN_BRIEF.md` を基準にアートディレクションを確立。レイアウトは罫線・余白・情報の編集に重心を置き、絵文字・無意味な大きいカード・大量の丸角・不必要なグラデーションを禁止。
- `visual-prototype/index.html` の既存デザインは『Editorial案A』とし、別の明確に違う方向性B/Cをローカルで作って**それぞれ375/390/430pxのスクショ**を作成。内容はリアルタイムを装わずデモ表示と明示。
- フォント（日本語/英数字）、字幅、見出し、行間、数字の桁表示、ダークモード、警報色を早期に試験。デザインレビューに必要なスクショ・理由・比較表を残す。UIの最終選定はユーザーの承認を受ける（承認前でも土台のローカル開発は進めてよい）。
- 外部写真を取得するなら利用権・出典を確認。AIで生成した景観を実際の奄美写真として見せない。

## Architecture & Data First

- `docs/FEATURE_AUDIT.md` と `docs/DATA_SOURCE_REGISTRY.csv` を使い、P0 / P1 / P2の機能をGitHub Issue相当のタスクに分解。
- 気象庁XML: 2026年の仕様更新、速報/訂正/取消・対象区域・発表時刻・取得時刻を適切に処理。無停止保証はない。P2P地震情報と混同しない。
- 台風以前: 公式「24時間以内に台風へ発達する見込みの熱帯低気圧」は表示対象。その前段階の全熱帯低気圧を網羅するとは**謳わない**。他のソースの利用規約/更新頻度/品質を調査し、採用前に報告。
- 地震速報: 地震発生後の震度情報、EEW、現在の津波警報を別々に実装。通知のタイムラグ、未配信、取り消しをテストし、OS標準の速報を代替しない。
- フライト/船舶/バス: 提供契約がないライブ情報を無断スクレイピングしない。公式リンクを有効にしたMVPにする。
- 災害ハザード: 奄美市の避難場所/浸水情報、ほか島内各自治体の管轄の差を明示。公式地図リンク優先、地図データのライセンスは別途確認。
- 移動用電話帳: 前回試作の値は再検証リスト。事業者に公開番号、サービス継続、掲載確認日を確認する前に『確認済み』としない。
- 外部データは共通API経由。`docs/TECHNICAL_BLUEPRINT.md` に沿ってAPI契約、キャッシュ、更新失敗、安全UIの仕様を実装。JSTを統一。

## 実装順序（ローカル）

**Phase 1**: 新しいExpo/TypeScriptアプリのスキャフォールドとナビ、5タブの空状態、デザインコンポーネント、モックAPI、地域/日付切替、データ状態モデル、エラー表示。

**Phase 2**: 既存SHIMA CRAFT潮・天気実装の確認、日の出/方位角のテスト、確認できた出典の共通API、移動/防災への公式リンク、安全な電話発信。P0機能を必要に応じて段階的に作成。

**Phase 3**: 公式データの実接続・イベント正規化、オフライン、保存/お気に入り、通知の同意フロー（通常通知のみ、配信基盤完成後）、統合・自動テスト、実機/エミュレータスクショ。

**Phase 4（要事前承認）**: GitHub Remote/Cloudflare Workerのデプロイ、TestFlight、Google Playテスト、一般公開。勝手にpush/deploy/ストア登録しない。
