# AMAMI LIFE — Design Direction v1 / 手作り感のある実用的エディトリアルUI

## なぜv0.3を踏襲しないか

前作のAIっぽさを生んだ主因は「同じ丸角カードを無限に積む」「意味のないグラデーション」「絵文字に頼るピクト」「画面の数字が等価」「余白の規則が曖昧」「データ異常時の表示が目立たない」。機能の数ではなく、**優先順位、編集、型・素材・レイアウトの一貫性**で品質を作る。

## 具体的アートディレクション

**ISLAND EDITORIAL UTILITY** = 島の小さなガイドブックと、精密な計器の間。

- 気取った南国広告ではなく、毎日使う生活道具。
- 背景に淡い紙の温度感、ボディに深い墨色。過度なガラスUI、蛍光色、AI生成の景色、絵文字、見た目だけのグラフを排除。
- テキスト・余白・罫線・写真のコントラストで階層化。写真は権利を確認した奄美実写のみ。写真なしでも成立する骨格。
- 1画面に主役はひとつ。今日なら「日の出・潮」、防災なら「現在取得できる公式情報・避難リンク」。
- 動きは200〜320ms程度、reduced-motion対応、情報切り替えに使う。常時動く装飾は不要。

## タイポグラフィ / 先にフォントを決める

- **日本語本文**：iOSはSystem UI（Hiragino Sansフォールバック）、AndroidはNoto Sans JPを第一候補。異なるOSで字幅・字面・行送りを実機確認し、必要ならアプリ内埋込を検討。
- **大きな日本語見出し**：限定的に明朝系（例：Shippori Mincho/端末の明朝）。防災・ボタンには使用しない。
- **数字・英字**：Inter等の可読性の高いサンセリフ、またはGeorgiaの控えめな見出し数字（プロトタイプの例）。**時刻は等幅数字**を優先。桁ずれ、AM/PM、タイムゾーンをチェック。
- 本文16sp/pt基準、二次情報13〜14、セクション16〜18、タイトル28〜34。10〜11は装飾ラベル限定で意味のある主要情報に使用しない。
- 日本語行間1.55〜1.7、英字ラベルは小さなletter-spacing可。日本語本文への過剰な字間・細いウェイト・縦長変形を禁止。
- 端末の文字サイズ拡大に対応、任意のフォントサイズで操作や警報が切れない。
- 実際に配布するフォントはライセンス/再配布条件を照合し、公式パッケージから取得。**ZIPにフォントファイルは含めない。**

## レイアウトグリッド / Navigation

- モバイル左右24px（狭い端末は20px）、余白は4/8/12/16/24/32の基準。8pxグリッドを基礎に視覚補正。
- セクションは余白または罫線で区切る。同一機能の羅列はフル幅リスト優先。**同じカードUIが3つ連続する画面をレビュー対象にする。**
- 主タブは **今日 / 探す / 移動 / 防災 / その他** の5つ固定。「潮と空」は今日に統合し、詳細への深掘りで提供。
- タップ領域最小44×44pt相当、親指で触りやすい配置、safe area、片手操作。Androidは戻るボタン/ジェスチャを尊重。
- 検索は横断設計（設備/事業者/地点）。フィルタと位置情報なしでも使える手動エリア切替。
- 「通知が来た場合」はプッシュ遷移後でも元の画面へ戻れる設計。強制ポップアップの乱用禁止。

## 5画面の骨格

1. 今日：場所、日付、太陽・潮など一日の要点、重要情報の状態、1タップで移動/防災。
2. 探す：用途で探す。カテゴリや検索、地図切替。実在POI以外をフェイクデータで本番に見せない。
3. 移動：飛行機、フェリー、バス、タクシー/代行。出発日/便の指定はデータ提供契約が整ってから。
4. 防災：まず公式ソースの状態。地震・津波、熱帯低気圧/台風、避難、気象警報、110/119。取得不能時の見せ方も主デザインと同じ重要度で作る。
5. その他：地域・通知・保存/オフライン・出典・利用規約・プライバシー・情報修正・SHIMA CRAFTクレジット。

## コンポーネントの型

`Typography` `DataTimestamp` `FreshnessState` `SourceAttribution` `WarningBanner` `FactRow` `TimeValue` `EmptyState` `OfflineBanner` `SectionHeading` `ListRow` `PressablePhone` `SafeAreaTabBar` `LocationPicker` `LinkToOfficial` `WeatherMetric`。すべてにアクセシビリティラベル/状態を持たせる。

## デザイン品質ゲート（自己採点ではなく実物で確認）

- 375×667 / 390×844 / 430×932の画面幅、iPhone SE級、Android異なるフォントレンダリングでスクショを保存。
- 次の5状態を各重要画面で描く：通常/読み込み中/空/通信失敗/古いデータ。防災はさらに解除と訂正、未確認。
- ダークモードで警報の可読性、VoiceOver/TalkBack、Dynamic Typeで潰れないか。
- 文字サイズを上げても主要操作ができる。長い地名/国際化にも耐える。
- 開発初期に**2〜3案の明確に違うデザインシステム**をモック/スクショで比較し、採用案を決定。強制的に本プレビューへ固定しない（現プレビューは基準候補）。
- ユーザーのフィードバックと可能なら**実際のプロのUIデザイナーによるレビュー**を受ける。Codexが人間デザイナーのレビューを受けたと主張してはならない。
