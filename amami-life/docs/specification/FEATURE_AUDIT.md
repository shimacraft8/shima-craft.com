# 機能の抜け漏れ調査・優先順位 / 2026-10-13

## プロダクトの主対象

- 旅行者：出発前 → 空港・港 → 移動 → 現地 → 帰路。情報探し時間を減らし、判断に使える公式情報へ最短で到達。
- 島民：普段の潮・天気・台風・交通・停電・医療・電話帳。「観光案内」だけでは利用頻度が続かない。
- 撮影・アウトドア利用：日の出/入り方位角、地点別潮汐、月齢、雲・波・風。参考値の限界と海況注意を明示。

## P0 — 最初の公開に必要な核

| 領域 | ユーザーストーリー / 機能 | 優先する理由 | ローンチ判定 |
|---|---|---|---|
| TODAY | 選択地点と日付、日の出/入り時刻・方位角、潮汐（満干と予測潮位） | 既存サイト資産を生かせる日常利用の柱 | エリア/日付/JST、実測/予測/補間を区別、空欄の整合性 |
| WEATHER | 地域別の天気/雨・風・波、警報の公式導線 | 地点差と欠測に対応 | 時刻、ソース、stale/unknown状態 |
| CYCLONE | 台風＋「24時間以内に台風へ発達すると予想される熱帯低気圧」から追跡、既存台風の更新/終息 | 発生初期から旅行変更に備える | ライブデータ提供契約 or 公式リンク、時点と台風識別子の明示 |
| EARTHQUAKE | 震源・震度・日時、津波警報/注意報の公式情報確認 | 海辺の避難に直結 | 最新地震情報と現在警報を混同しない |
| EVACUATION | 津波避難場所、市のハザードマップ（津波・洪水・土砂）、110/119 | 地震速報だけでは不十分 | 公式情報への遷移、避難場所の最終確認日 |
| AIR | 奄美空港の公式運航状況と空港アクセス | 旅行の生命線 | 公式リンク起点。API/転載権限がなければ独自の運航判定はしない |
| SEA TRANSPORT | A''LINE、マリックスラインの運航情報・条件付き運航・寄港地変更 | フェリーが台風に左右される | 会社別の公式ページ、運航日と対象便の取り違え防止 |
| BUS | しまバスの路線/時刻表/運行お知らせ | レンタカー未利用者への必須情報 | ダイヤ改正日、静的PDF等への公式導線 |
| CONTACTS | タクシー・運転代行・空港・バス・医療等の検索とワンタップ電話 | 緊急時にも役立つ | 掲載の適法性・番号・営業エリアの確認日が必須 |
| OFFLINE | 保存済み電話帳、避難の連絡先、公式リンク先リスト、取得済み旅のメモ | 圏外/停電でも最低限使える | 初回同期と情報の最終更新日を明示。オンライン速報との区別 |
| UX | 「今日/探す/移動/防災/その他」の5主要画面＋横断検索 | 機能が増えても迷わない | 主要操作3タップ以内、アクセシビリティ、実機チェック |
| TRUST | 出典、発表時刻、取得時刻、未更新・通信失敗、訂正/解除の処理 | 速報系を誤解させない | 「データ未取得=安全」の判定ゼロ |

**P0の実装は必ずしも全データをアプリ内に転載することではない。** 利用許諾が取れない、リアルタイム取得が安定しない場合は、公式リンク＋更新日・簡潔な説明で公開品質を守る。

## P2 — 安定稼働後の差別化

- 旅行期間中だけ使えるカスタムホーム、ショートカット、Apple/Androidのウィジェット
- 地域事業者が自ら掲載情報を修正申請する管理画面（承認制、改ざん監査）
- オフラインの地域マップ（合法的なオフラインタイルの利用権が必要）
- 店舗予約/宿/レンタカー連携、観光モデルコース、交通アラートのカスタマイズ
- 管理分析：GA4/Firebase等、プライバシー保護の集計・離脱・お気に入り機能利用状況、広告実装は別途判断

## 見落としやすい重大事項

1. 奄美「大島」だけでなく、瀬戸内町など自治体ごとに避難場所の管理主体が異なる。奄美市データだけで島全域をカバーしたと称さない。
2. 台風が温帯低気圧・熱帯低気圧に変わった後も危険は残る。変化＝解除ではない。
3. 過去72時間の関連XML発表は「現在発生中の台風一覧」「現行警報の有無」ではない。旧試作を本番に流用する際、イベントIDと訂正・取消・更新系列の統合必須。
4. 近隣地点で日の出角度・潮位が変わる。単一の名瀬基準を「奄美大島全域」値にしない。
5. 潮の予測値と実況値、線形補間値を分ける。海の安全判断は波・うねり・風・公式規制を確認。
6. タクシー/運転代行は電話番号だけでなく地域・営業時間・支払方法・更新日、取消受付が必要。
7. フライト・フェリーの公式サイトへのリンクは原則可能だが、スクレイピングや継続転載は別問題。条件確認のうえ提供事業者へ正式照会。
8. ネイティブ通知許可を最初に強要しない。重要情報の通知は明示的に選択、解除/修正/重複を抑制。
9. 緊急地震速報の「緊急通知が必ず鳴る」は保証できない。端末標準の速報を無効にしないよう案内。
10. Googleマップ情報の無断コピーやOSM公共サーバーの一括タイルダウンロードを設計に入れない。
11. 空港/船の運航状況は「今日」「便の日時」「更新時刻」に注意。事前に予約した便との同定も必要。
12. 観光スポット画像は撮影・使用権を確保。AI生成景色を実在スポットの写真として誤認させない。

## 制約付きの早期熱帯低気圧監視

気象庁の台風経路図に含まれる「発達する熱帯低気圧」は **24時間以内に台風へ発達するとの予報が出ている場合**。すべての熱帯低気圧の発生段階の網羅ではない。別の公的機関・商用APIを採用するなら、予報精度、確定/速報の違い、転載権、更新間隔を確認。独自計算で「奄美に直撃確定」などと断定しない。
