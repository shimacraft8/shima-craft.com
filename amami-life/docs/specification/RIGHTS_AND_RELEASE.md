# 権利・品質・一般公開の必須確認

## 情報源の利用

1. 気象庁XMLは商用利用に制限がないと公式FAQに記載。ただし発表元明示、利用条件、停止/遅延の可能性、仕様変更の追跡が必要。公式 `https://xml.kishou.go.jp/qanda.html` / `https://xml.kishou.go.jp/xmlpull.html`。
2. 台風・熱帯低気圧の自動判定には現行電文状態を正規化し、見込み・予報円・警報/注意報の意味を正確に伝える。https://www.jma.go.jp/jma/kishou/know/typhoon/7-1.html
3. 空港・フェリー・バスの運航情報は、リンク掲載とアプリ内転載/スクレイピングが別。公式APIの有無・利用条件・再配信の契約を事業者に確認。
4. 電話帳は番号・事業者名・営業地域・掲載日を各社確認。誤情報の報告・修正/削除窓口を作る。
5. ハザードマップは自治体ごとに利用条件や縮尺がある。再配布許諾が不明な段階では**公式地図を開く導線**とし、危険/安全判定用の独自GISにしない。
6. OpenStreetMapの地理データ（ODbL）と公共地図タイル（別運用ルール）は異なる。公共タイルの事前一括DL/オフライン配布は禁止（https://operations.osmfoundation.org/policies/tiles/）。Nominatimの公開APIは重い一斉照会、オートコンプリートなど禁止（https://operations.osmfoundation.org/policies/nominatim/）。
7. 写真は撮影者・被写体・施設許諾の記録を残し、別のサービス/AIで生成した景観を現地写真と誤称しない。

## 安全と通知

- 防災機能は地域の正確性、遅延、冗長経路、最新取得日時の監視を優先。重要な警報が未取得の状態では「警報なし」と表示しない。
- 緊急地震速報・津波警報はOS標準のJアラート系/緊急速報と同等と表現しない。バックグラウンドプッシュ・緊急通知の遅延・許認可を調査。危険な場所ではまず避難を案内。
- 津波・海況では安全を保証しない。海上保安庁の沿岸情報や地元自治体の規制を確認。

## iOS / Android公開

- Apple App Review 4.2: 単なるWeb再包装・リンク集ではなく、ネイティブ機能、保存、通知（実装時）、場所選択、使いやすい情報比較を提供。https://developer.apple.com/jp/app-store/review/guidelines/
- Appleアカウントの個人名義だと販売元に本名が表示され得る。SHIMA CRAFTブランド名で運用したい場合、法人等の組織登録要件を調査し、**登録主体を先に決める**。個人登録や本人情報の露出を勝手に決めない。
- Google Playの開発者本人確認/テスト要件・Data Safety等の最新条件を公開時に再確認。
- 位置情報・通知・連絡先の権限は機能を使う瞬間に説明、同意を取る。無料・ログイン不要で利用可能な価値を先に提供。
- プライバシーポリシー/利用規約/問い合わせ/データ訂正窓口、アプリアイコン、スクショ、ストア説明（日英）、年齢レーティング等を公開前に整備。
- TestFlightとGoogle Playのクローズドテストを実施。低速回線、オフライン、時刻ズレ、警報更新、端末ダークモード、文字拡大などで検証。

## 決して自動実施しないもの

本番Cloudflare Workersへのdeploy、既存サイト本番の変更、GitHub push/PR、Apple/Googleへの登録・リリース、課金開始、外部事業者名での公開、登録名義の確定。Codexは各段階でユーザーの明示許可を得る。
