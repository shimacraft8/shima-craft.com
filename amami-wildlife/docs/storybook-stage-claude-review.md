# 体験型絵本のClaudeレビュー

モデル: claude-opus-5 / effort high / 読み取り専用。

コード4点＋スクリーンショット2点＋app.js を読み、編集は一切していません。結論から言うと **方向性と完成度は「普通のスクロールサイト」をはっきり超えています**。絵本の比喩（表紙→森→渓流→海→巻末、紙がめくれる陰影、キャプション札）は成立していて、捨てる理由はありません。残っているのは「仕上げ」の問題で、全部小さな修正で潰せます。

---

## A. 機能的な不具合・リスク（優先度順）

**1. 2ページ以上の飛び先が1ページしか進まない可能性（最優先）**
`storybook.css:23` の `scroll-snap-stop:always` と `index.js:52` のプログラム的 `scrollTo({behavior:'smooth'})` が衝突します。Chromium系では snap-stop がスナップ点の飛び越しを禁じるため、「表紙→巻末」「Home/End」「章ナビで2つ先」が隣のページで止まりがちです。JS側は先に `markIndex`+`pushState` を済ませているので、カウンタ・URL・進捗バーが実位置とズレ、`onSettle`(640ms) でようやく自己修復＝ユーザーには「章ナビが効かない」と見えます。
→ 修正: `|Δ|>1` のときだけ track に `.is-jumping` を付け `scroll-snap-type:none` にし、`onSettle` で外す。副作用のない数行です。

**2. モバイルのステージ高さが固定660px**
`storybook.css:286` が `:182` の `clamp()` を上書きして `height:660px` 固定。ヘッダ76px＋余白＋660px で、**「前/次のページ」バーと操作ヒントが初期表示の外**に出ます（＝横めくりの存在に気づけない）。横持ちスマホはさらに深刻で、短背面の救済 `:244` は `min-width:761px` 限定のため効きません。
→ 修正: `clamp(420px,calc(100svh - var(--story-header) - 150px),660px)` に戻し、`:244` の幅条件を外す。

**3. 非表示ページのリンクがタブ順に残る**
`storybook.css:26` はマウスだけを殺しており、キーボードでは画面外4ページ分（約20リンク）を巡回できます。`index.js:74` の focusin→`goTo` で追従はしますが、Shift+Tab で逆向きにページが勝手にめくれ、履歴も積まれません。
→ 修正: `paint()` 内で `|p|>1.02` のスロットに `inert` を付与（`story-ready` 時のみ）。JS無効時は従来どおり全リンク到達可能なのでフォールバックは壊れません。focusin ハンドラも不要になります。

**4. 履歴の挙動が入力手段で食い違う**
キー/ボタン/リンクは `pushState`（`index.js:72,90`）、タッチ・トラックパッドのスワイプは `replaceState`（`:61`）。同じ「1ページめくる」なのに戻るボタンの意味が変わり、矢印キー長押しで履歴が積み上がります。
→ 修正: **めくりは全て `replaceState` に統一**（戻る＝絵本から出る）。`pushState` はダイアログ（図鑑ページ）だけに残す。ヒント文にも1行添える。

**5. 小粒だが確実なもの**
- `#book-art` に `onerror` が無い（写真側 `:131` にはある）。イラスト404で壊れ画像が出ます。
- `measure()` が `--story-header` を書き、その値が `.stage-viewport` 高さを決め、その viewport を ResizeObserver が監視（`index.js:14,117`）。収束はしますが ResizeObserver loop 警告が出る構成。値が同じなら書かないガードを。
- IntersectionObserver に閾値なし（`:120`）＝1px見えただけで19秒の光と4.5秒のリングが回り続ける。`{threshold:.15}` で十分。
- `goTo` は `width===0`（印刷・非表示タブ）でも index と URL だけ進む。`if(!width)return` を。
- `aria-labelledby` が素の `<li>` に付いている（`storybook.py:25`）。`<article class="spread-paper">` 側に移すと名前が実際に読まれます。

**検証して問題なかった点**: CSPは `el.style.setProperty`（CSSOM）なので非該当、`slot()` も `style=''` で空のまま＝インライン残留なし。JS無効時は実アンカー＋ネイティブsnapで5ページが素直に読め、`#colophon` のid整合も取れています。reduced-motion はOSクエリと `motion-paused` の二重で `!important` リセットされ、めくりも即時化。アイドル時のrafループ無しも実装どおり。40点の写真・図鑑・species データは無傷です。

## B. 絵としての詰め（クリエイティブ側）

**6. ホットスポットの白リング＆↗が絵を汚している（PC最大の粗）**
`storybook.css:276` の `inset:22px 28px` は100×88のチップ内で約50pxの円になり、**生き物の胴体を横切る白い弧**として写っています（ルリカケスの翼上、クワガタ）。↗バッジ（`:279`）も右上に離れて浮き、埃のよう。
→ 修正: 平常時はリングと↗を消し、ホバー/フォーカス時にリング＋名前＋↗を一緒に出す。絵の上では「接地影」だけで十分な誘目性があります。

**7. 小動物が宙に浮いている**
`:277` の `drop-shadow(0 5px 5px)` が密着しすぎで、鳥も蛇もステッカー化。鳥に至っては止まる枝がありません。
→ 修正: 二段の影（`drop-shadow(0 2px 2px #0a2a1a66) drop-shadow(0 14px 10px #0a2a1a4d)`）に変え、`--sy` を画面内の実際の面（シダの葉・地面）へ数%寄せる。ルリカケスは 59%/62% → 枝のある位置へ。これだけで「描き込まれた絵」に見えます。

**8. 静止時に「本」の手がかりが無い**
めくる瞬間だけが本で、止まると横長バナー。`.stage-viewport`（`:19`）の右端に2〜3本のヘアライン（小口＝ページ束）と左端に薄いノド影を足す。CSS8行で体感品質が一段上がります。

**9. 奥行きのカメラが各ページ別々**
`perspective` が `.stage-slot` ごと＋`perspective-origin:50% 50%`（`:23`）なので、画面外のページは自分の中心に消失点を持ち、2枚の紙が別カメラで回ります。
→ 修正: `perspective-origin:calc(50% - var(--p,0)*50%) 50%` の1行で視点をビューポート中央に固定。めくりの違和感が消えます。

**10. モバイルでは絵本が「画像＋ボタン一覧」に退行**
`:204`／`:298` の白チップが全幅リスト化し、ステージの35%前後を占有。スクショでも下3行がメニューに見えます。
→ 修正: チップを暗いガラス（`#0e211ad9` ＋ `1px #ffffff40`、文字は白）にして2カラム化。サムネは残す。絵の面積が戻り、「絵の中のキャプション」として読めます。

**11. モバイルの絵が縦に切り抜かれすぎ**
3:2の風景画を縦長枠に `object-fit:cover`（`:34`, `58% 54%`）＝横の3割程度しか見えず、光芒が失われています。
→ 修正: 760px以下だけ景色ごとに `object-position`（森なら `50% 40%` 付近）を指定。新規作画は不要です。

**12. モバイル右上の丸い→ボタン**（`:314`）がヘッダ直下のシステムUIに見え、「前へ」が対になっていない。絵の右下へ移すか、ビューポート内に小さく `01/05` を併置すると、横めくりの存在も同時に伝わります。

**13. ウミガメだけホバーが死んでいる**
`:74` の `translateY(-7px)` を `:310` の `lagoon-drift` が同じ `transform` で上書き。漂いを内側の span か `rotate` 側に逃がすと挙動が揃います。

## C. 保守

`@media(max-width:760px)` が3ブロック（`:175`/`:285`/`:313`）、スポット座標と `.stage-slot{scroll-margin-top}` が二重定義（`:23`/`:272`、`:268`/`:282`）。動作はカスケード順で正しいものの、修正層が積み上がった状態で、**次の1手を間違ったブロックに当てる事故**が起きやすい。挙動を変えない統合を一度だけ入れておくことをお勧めします。

---

**推奨着手順**: 1 → 2 → 6 → 7 → 3 → 10 → 9/8。1と2は「壊れて見える」系、6と7は「絵の格」に直結、8と9は投資対効果が最大です。全てピンポイントの差分で、再設計は不要です。

## 修正と判断

- 複数章ジャンプ中だけsnapを外し、完了後に復帰。実ブラウザーでHome/End・連続操作・履歴を照合。
- 固定660pxをやめ、小画面を560〜700pxの可変高に。主役/関連リンクの重なりを解消。
- 非表示の4ページをinert化。フォーカスは絵本内の有効な位置へ。
- 戻るで前の章へ戻れる仕様を維持し、ネイティブスワイプも確定時に1回だけpushする構成へ統一。キー長押しの重複を抑止。
- イラスト失敗表示、ヘッダー測定の同値ガード、15%交差しきい値、articleの名前付けを追加。
- PCの白リングを廃止。名前/矢印はhover/focusで表示。動物同士が重ならない座標へ。
- 本の小口、ノド影、共通の視点位置、静止画面の手がかりを追加。
- 小画面は暗いキャプションを2列配置。風景ごとに切り抜き位置を調整。
- ウミガメはhover時に漂いを止め、影と明るさで反応。
- CSSの末尾にはレスポンシブ/静止モードの意図的な上書きが残る。公開挙動を優先し、無関係な全面整理は行っていない。

初期の実装依頼は20ツールターン上限で終了したため、Codexが差分を精査し、残りの修正・ビルド・実動作確認を継続した。Claudeの肯定的な評価を、受賞実績や品質保証として扱わない。
