# 白黒写真カラー化 費用監査（2026-07-02）

## 結論

- **A. 画像処理1回ごとの外部API従量課金: なし（達成）**
  推論は利用者のブラウザ内で実行され、Replicate等の外部AI APIへのリクエストは存在しない。
  `REPLICATE_API_TOKEN` への参照もコードから削除済み。
- **B. 運営費が永久に完全ゼロ: 保証しない**
  ホスティング（Vercel）と独自ドメインの費用は従来どおり発生する。下記の帯域条件も参照。

## 費用項目の監査

| 項目 | 内容 | 費用 |
|---|---|---|
| 画像1枚ごとの外部API料金 | 外部APIを呼ばないため存在しない | 0円 |
| モデル配信帯域 | fp16 68.5MB（WebGPU端末）または int8 43.6MB（WASM端末）+ ORTランタイム約27MB。**初回のみ**。2回目以降は Cache Storage により再ダウンロードなし | Vercel帯域を消費 |
| Vercel帯域の目安 | 新規利用者1人あたり最大約96MB（fp16+ランタイム）。Hobbyプランの無料転送量 100GB/月 ≒ **月あたり約1,000人の新規利用者まで無料枠内**。超過時はVercelから通知があり、Pro移行（$20/月）または `COLORIZE_ENABLED=false` での一時停止で対処 | 条件付き0円 |
| ビルド時間 | モデルは `public/` の静的ファイルでビルド処理を通らない。ビルド時間への影響は数秒（コピー）程度 | 0円 |
| Gitリポジトリ容量 | +約139MB（モデル2つ + ORTランタイム）。GitHub無料枠（推奨1GB・1ファイル100MB制限）内。Git LFS不使用 | 0円 |
| ストレージ | Vercelの静的アセットとしてデプロイに含まれる。Blob等の課金サービス不使用 | 0円 |
| Analytics送信内容 | 既存GAイベントのみ（colorize_start/success/error/cancel/download等）。画像データ・画素データは送信しない。successイベントにbackend種別と処理時間(ms)のみ追加 | 0円 |
| エラートラッキング | 外部エラートラッキングサービスは不使用。エラーは画面表示とGAイベント（コードのみ）に留まる | 0円 |

## モデル配信方式の比較（採用: リポジトリ内 public/ 配信）

| 方式 | 費用 | 不採用理由 |
|---|---|---|
| public/ 配信（採用） | Vercel帯域内で0円 | — |
| Hugging Face hosting | 0円 | 匿名ダウンロードのレート制限・規約/仕様変更への依存。外部障害点が増える |
| jsDelivr | 0円 | npm/GitHub配布物向けであり、生成モデルの配信は本来用途でない |
| GitHub Releases | 0円 | CORS・リダイレクト対応が必要になり構成が複雑化 |
| Vercel Blob | 従量課金 | 帯域・オペレーション課金が発生しうる |

## 帯域リスクの緩和策（実装済み）

1. モデルはページ表示時ではなく「カラー化を開始する」押下時に初めてダウンロードする
   （ページ閲覧だけの訪問者は帯域を消費しない）。
2. Cache Storage API による端末キャッシュで、同一端末の2回目以降のダウンロードをゼロにする。
3. WebGPU端末はfp16のみ・WASM端末はint8のみをダウンロードし、両方は取得しない。
4. `COLORIZE_ENABLED=false` で「試験提供を一時停止しています」表示に即切替できる。

## 監視すべき指標

- Vercelダッシュボードの Fast Data Transfer（無料枠100GB/月に対する消費）
- GA の colorize_start イベント数（新規モデルダウンロード数の近似）
